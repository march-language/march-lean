# A1 accept-side skip ledger.
#
# Enumerates every specs/lang/types/accept/*.march file that march-lean-check
# (A1) currently reports `skip` on — i.e. a file that DOES type/reject in
# march but whose declaration lies outside (or contains a subterm outside)
# the A1-modeled fragment (Check.lean / Linearity.lean), so the Lean side
# declines to render an independent verdict rather than risk a false
# MISMATCH.
#
# This is the coverage-tracker half of the harness's skip-ledger check
# (scripts/conformance-harness.sh): every path listed here MUST still be
# `skip` on the current corpus run, and no ADDITIONAL accept file may be
# `skip` — either direction fails the harness (see "skip-ledger enforcement"
# there). A file moving off this list (because a later task widens the
# fragment to model it) is expected and GOOD; delete its line when that
# happens. A file appearing here that the harness no longer observes as
# skip is a stale ledger, not a bug — update this file. A NEW file showing
# up as skip that isn't listed here is a genuine coverage regression.
#
# Scope (deliberate): only ACCEPT-side skips are enumerated. Every
# reject/*.march file skips too (A1 doesn't model the reject side at all —
# it only independently re-verifies accepts), which is a structural,
# always-true consequence of the A1 design, not a shrinking coverage
# tracker; enumerating it here would add 82 lines of noise the harness
# checks separately (see conformance-harness.sh's reject-side skip
# short-circuit) and would never usefully shrink.
#
# One relative path (from CORPUS_DIR) per line, trailing `# reason` comment.
# Regenerate by rerunning the harness and diffing its skip-file list against
# this file (a failing "SKIP-LEDGER MISMATCH" run prints exactly that diff).
